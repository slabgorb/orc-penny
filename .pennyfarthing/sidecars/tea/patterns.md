<pattern name="to-thread-on-async-fn-missing-await-red">
160-20 (Frame brownfield routes): the bug class is `await asyncio.to_thread(fn, ...)` where `fn` is itself an `async def`. `to_thread` runs `fn(...)` in a worker thread, which only *creates* a coroutine (body never runs) and returns it un-awaited → `result` is a coroutine object → "coroutine never awaited" RuntimeWarning + downstream `len(result)`/JSON-serialize raises → route 500s. **First move: verify the helper signatures** — `grep "def <helper>"` and confirm `async def`. If async, `to_thread` is wrong; the fix is `await fn(...)` direct. The KILLER fix-agnostic RED is the **executed-flag**: monkeypatch the helper (where used — `analysis.find_stale_files`, lang-review #6) with `async def fake(*a, **k): flag["ran"]=True; return <real Result>`. On the broken to_thread path `fake(...)` is *called* but its body NEVER runs (only an awaited coroutine executes its body), so `flag["ran"]` stays False; the only way to flip it True is a direct `await`. Assert `flag["ran"] is True` + status 200 + a sentinel from the returned Result appears in the body. Use `*a, **k` on the fake so it survives whether Dev passes `str` or `Path`. **Probe for SECONDARY bugs the await masks** (the coroutine error 500s before they fire): here `get_dead_code` did `len(result)` but `find_stale_files` returns a `DeadCodeResult` dataclass (no `__len__`) → still 500 after the await fix; and `analyze_complexity`/`analyze_dependencies` do `target_path.resolve()` (Path-only) while the route passes a `str` project_dir → `AttributeError`. Catch these with a **Layer-2 real-helper test**: set `PF_PROJECT_DIR=str(tmp_path)`, hit the route through `TestClient(create_app())` with NO monkeypatch, assert 200 + a real `*Result` key (the helpers degrade to `success=False` when git/eslint/npm are absent — never raise — so a *correctly* fixed route ALWAYS 200s, never 500). Layer-2 stays RED through await-only fixes, forcing the complete fix per AC2 "return real results". Log the secondary-bug forcing as Design Deviations + blocking Delivery Findings. NB: the bug is module-wide (every route in `analysis.py` wraps an async helper in to_thread — hotspots/health-score/code-markers too) but the story scoped 3 routes → test the 3, flag the siblings as a non-blocking Delivery Finding. Result: 3 (Layer-1) + 3 (Layer-2) = 6 red, 0 errored.
</pattern>

<pattern name="vacuous-status-tolerance-masks-route-bug">
The reason 160-20's broken routes shipped: the existing `test_frame_routes.py` checks were `assert response.status_code in (200, 500)` + `isinstance(data, dict)` — a 500 crash PASSES. A status-code *set* that includes the error code, or `isinstance(data, dict)` on an `{"error": ...}` shape, is a vacuous assertion that masks total route failure. When REDding a route bug, your new tests MUST pin the *success* contract (`== 200` + a real-result key), and flag the lax sibling tests as a non-blocking Delivery Finding (don't necessarily edit another story's tests in RED, but name them as the pipeline gap that let the bug through — SOUL #1).
</pattern>

<pattern name="exception-taxonomy-red">
When REDding a fail-loud fix around file reads, cover the FULL raisable taxonomy of the guarded call, not just the obvious malformed case: `Path.read_text()` raises (a) `yaml`-level parse errors AFTER decode, (b) `UnicodeDecodeError` (a ValueError — escapes `except OSError`!) via `write_bytes(b"caf\xe9 \xff\xfe")`, (c) `PermissionError` via `shard.chmod(0o000)` (guard with `skipif(os.geteuid()==0)` and restore perms in `finally` or tmp_path cleanup breaks), (d) FileNotFoundError (usually owned by a downstream exists()-gated warning — pin that it stays SILENT at the load layer). Story 160-4 round 1 covered only (a)+(d); Reviewer rejected on (b) — a regression where the narrowed catch crashed the whole fetch on develop-survivable input. Pin warning text by FILENAME pattern only + a negative ("not found" must not appear for present files); leave wording to Dev. Same lesson as Dev's narrowed-exception gotcha, from the test side: enumerate the taxonomy FIRST, in round 1.
</pattern>

<pattern name="source-removal-red">
To RED a "delete this function + its call sites" AC robustly (153-12 AC1/AC2): pair a **behavioral** check with a **source-scan**. Behavioral: `assert not hasattr(module, "_fn")` (def gone) and `assert "param" not in inspect.signature(fn).parameters` (signature cleaned) and `CliRunner().invoke(cmd, ["--help"])` output lacks the flag. Source-scan: `assert "_fn" not in Path(module.__file__).read_text()` — this is the only cheap way to assert *call sites* (not just the def) are gone, which the AC usually demands ("both call sites gone"). hasattr alone passes if the def is deleted but a call site lingers (would only fail at runtime). <pattern name="gate-admonition">
Frame all mandatory steps as blocking admonitions, never suggestions. Use "Do not proceed with [next action] until [condition]" — not "you MUST", "please check", or "you should". Models treat suggestions as optional under pressure; admonitions define a precondition that blocks progression.
</pattern>

<pattern name="suite-side-effect-meta-test">
When the bug is a test *leaking* a side effect onto the real repo/filesystem (not a source defect), the source-level fix is often already in place — verify it first. The faithful RED test then has to observe the offending test's behavior, so write a **meta-test**: spawn `sys.executable -m pytest <abs path to offending file> -k <selector> -q` in a `subprocess` with `cwd=` and `PROJECT_ROOT=` pinned to a `tmp_path` sandbox repo (mimic enough of the real layout — e.g. a `develop` branch and a `.pennyfarthing/` marker — that the leak path actually fires), then assert the sandbox is unchanged (e.g. branch still `main`). Guard against false-green by asserting the inner run actually executed ("no tests ran" not in stdout). RED now / green once the offending test uses `tmp_path`. Pair it with a cheap **static guard** (`assert 'Path(".")' not in offending_file.read_text()`). Drives a test-hygiene fix WITHOUT forcing a spurious source guard. Story 153-9.
</pattern>

<pattern name="markdown-gate-not-enforced">

Story 158-3: setup→red advanced with no `sprint/context/context-{epic,story}-*.md`; guard keyed on `gate_type == "sm_setup_exit"`, presence+non-empty (mirrors the gate's documented Fallback, NOT the full schema validator). <pattern name="swallow-hides-constant-bug-red">
When REDding a fail-loud fix on a broad `except Exception` swallow, PROBE whether the swallow hides a CONSTANT code bug (a call that ALWAYS raises) vs a runtime present-but-broken input — they need different tests. Story 160-15 (ws_push fail-loud sweep part 2): `fetch_context`'s `except Exception: return {None-shape}` hid `config = ContextConfig(project_dir=project_dir)` raising `TypeError` on EVERY call (`ContextConfig` has no `project_dir` field; `check_context`'s real signature is `check_context(explicit_session=None, project_dir=None)` and builds its own config). So the "degraded shape" was constant and the panel had NEVER worked. Diagnostic tell: a green-guard that patches the seam to return a HEALTHY result and asserts real data BACK still fails with the degraded shape → the failure is upstream of the seam, i.e. a wiring bug, not a missing warn. Consequence for the fix: a naive "add a warn" would fire on every poll (the bug is constant) — so the story's fail-loud scope MUST include the root-cause wiring fix (SOUL #1), else fail-loud regresses UX to warn-spam. Encode this by making the healthy-path test patch ONLY the seam (`monkeypatch.setattr(cw, "check_context", lambda *a, **k: SimpleNamespace(percent=.., tokens=.., status=..))`) and deliberately NOT patch the broken constructor — the ONLY way to reach the healthy assertion is for Dev to call the seam correctly. Use `lambda *a, **k:` so the patched seam survives BOTH the current broken call and the fixed `check_context(project_dir=...)` call. Log as a Design Deviation (fix is root-cause, not just a warn) + a blocking Delivery Finding (the latent bug). For the sibling RED warn-tests, also patch the seam so the failure under test is the intended one (seam raises / returns degraded), not the incidental constructor TypeError.
</pattern>

<pattern name="inner-try-must-stay-warn-in-place-red">
