### Devil's Advocate

*Arguing this code is broken:*

A malicious analyst could craft a query with parentheses embedded in string literals to trigger false-positive depth rejection: `field = "((((((((((((((((...)))))))))))))))))"` — the pre-parse depth check at `parser.rs:42-61` counts ALL `(` characters including those inside quoted strings. With `MAX_NESTING_DEPTH=128`, an analyst who legitimately needs to match a string containing 129+ parentheses would get a spurious "nesting depth exceeded" error with no way to work around it. This is a correctness bug, not just an over-approximation — it makes valid queries unreachable.

The `kw()` function at `parser.rs:109` uses `eq_ignore_ascii_case` which means it accepts any identifier that matches the keyword pattern. But `kw()` consumes any identifier-like token and then checks if it matches — this means `SELECT` in filter position would be consumed by `kw("SELECT")` in the SQL branch before the filter branch gets a chance. The `choice()` at `parser.rs:99` tries SQL first, so a filter query starting with a field named `select` (e.g., `select_count > 5`) would be partially consumed by the SQL parser's `kw("SELECT")` matching `select`, then fail at `FROM`. This is a mode detection collision. **However**, I verified that `kw("SELECT")` consumes `select_count` as one token (since `_` matches `c.is_alphanumeric() || *c == '_'`), then `eq_ignore_ascii_case("SELECT")` fails on `select_count`, so this is not actually a bug — the keyword boundary check via identifier-character-only matching prevents partial consumption.

The `FieldRef` changes added an `array_indices: Vec<bool>` field with `#[serde(default)]`. This means existing serialized FieldRefs (from other crates, databases, or API payloads) that lack the `array_indices` field will deserialize with an empty `array_indices` vec. When `has_array` is true but `array_indices` is empty, the `Display` impl at `parser.rs:81` falls through to the simple `segments.join(".")` path — losing bracket notation. This is a backwards-compatibility regression for any existing serialized FieldRefs with array indices. **This is a real concern for Story 5.3+ when serialized ASTs may cross crate boundaries.**

The dead code at `parser.rs:42-48` wastes CPU cycles on every parse call iterating the entire input string for a computation that's immediately discarded. On a 1MB input at the length limit, this is ~1M character iterations for nothing.
