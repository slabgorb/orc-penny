### Delivery Findings

- **Gap** (non-blocking): Current `ApiResponse<T>` in axiathon-core has `meta: Option<ApiMeta>` with only pagination fields (`total`, `limit`, `offset`). The AC requires `meta` to always be present with `request_id`, `timestamp`, `trace_id`. The server layer will need to either extend `ApiMeta` or wrap it with a new response meta type.
  Affects `crates/axiathon-core/src/types.rs` (ApiMeta struct needs request_id/timestamp/trace_id fields).
  *Found by TEA during test design.*

- **Gap** (non-blocking): Current `ApiResponse<T>` uses singular `error: Option<ApiError>` but the AC specifies `errors` as an always-present array. The server layer will need to adapt this to array format.
  Affects `crates/axiathon-core/src/types.rs` (error field should be errors array).
  *Found by TEA during test design.*
