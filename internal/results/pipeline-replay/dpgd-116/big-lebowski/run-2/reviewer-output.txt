### `[HIGH]` `RawConfig` silently ignores unknown TOML fields — config typos go undetected

**File:** `config.rs:18-25`

```rust
#[derive(Debug, Deserialize, Default)]
struct RawConfig {
    #[serde(default)]
    server: RawServerConfig,
    #[serde(default)]
    output: RawOutputConfig,
}
```

serde's default behavior accepts unknown fields. A user who writes `[servr]` (typo) or `[auth]\ntoken = "..."` gets zero feedback — the typo section is silently ignored and defaults are used. The `config_file_rejects_token_field` test at `config_loading.rs:184-209` actually demonstrates this: `[auth]\ntoken = "..."` is silently swallowed, and the test accepts *either* Ok or Err. The test is vacuous — it can never fail.

This is particularly dangerous because AC-8 says "Tokens in OS keychain, NOT config file." If a user puts a token in the config file, the tool silently ignores it with no warning. The user thinks they're authenticated; they're not.

**Fix required:** Either add `#[serde(deny_unknown_fields)]` to `RawConfig`, or at minimum log a warning when unknown sections like `[auth]` are present.

### `[HIGH]` `with_env_override` silently swallows invalid `AXIATHON_TIMEOUT`

**File:** `config.rs:106-109`

```rust
"AXIATHON_TIMEOUT" => {
    if let Ok(t) = value.parse::<u64>() {
        self.timeout_secs = t;
    }
}
```

If `AXIATHON_TIMEOUT=abc`, the parse fails and the value is silently ignored. The user set an env var expecting it to take effect — it didn't, with no indication. There IS a `with_env_override_result` that returns an error, but `with_env_override` (no `_result`) is the one called in the layered override chain. Nothing in `main.rs` actually calls either method — the env var override chain isn't wired up in the binary entry point at all.

**Fix required:** Either (a) remove the non-result version and always use `with_env_override_result`, or (b) wire up actual `std::env::var` reads in `main.rs` using the error-returning variant.

### `[MEDIUM]` Shell completion silently returns nothing for unsupported shells

**File:** `commands/completion.rs:15`

```rust
_ => return, // Unsupported shell — write nothing
```

This path is unreachable from `main.rs` because `ShellType` is a clap `ValueEnum` (only bash/zsh/fish/powershell). **Fix required:** Return `Result<(), CliError>` from `generate_completion`, or make it accept `ShellType` instead of `&str` to leverage the type system.
