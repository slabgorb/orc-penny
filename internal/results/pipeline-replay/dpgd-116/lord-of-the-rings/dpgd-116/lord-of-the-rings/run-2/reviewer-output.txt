### **[HIGH] Nightly rustfmt fails — 635 lines of import ordering diff** at `crates/axiathon-client/src/*.rs`

Per `gotchas.md`: *"Always include `cargo +nightly fmt --all --check` in the preflight. Nightly rustfmt enforces import ordering that stable does not. If it fails, flag it before approval — don't let it slip to post-merge."*

Import ordering violations across `cli.rs`, `completion.rs`, and likely other files. The nightly formatter also wants to merge split derives (e.g., `#[derive(Parser)]\n#[derive(Debug)]` → `#[derive(Parser, Debug)]`). This is a blocking finding per project gotchas.

### **[HIGH] `ClientConfig::default()` skips validation on env var overrides** at `config.rs:27-36`

`Default::default()` calls `apply_env_overrides()` which blindly accepts whatever `AXIATHON_API_URL` provides — no scheme check, no credential-in-URL check. The `from_file()` and builder paths correctly call `validate()`, but `default()` does not. If `AXIATHON_API_URL=ftp://evil.com` is set, `ClientConfig::default()` produces an invalid config that passes silently.

```rust
// config.rs:27-36 — no validate() call after apply_env_overrides
impl Default for ClientConfig {
    fn default() -> Self {
        let mut config = Self { ... };
        config.apply_env_overrides();  // ← no validation after this
        config
    }
}
```

### **[MEDIUM] `with_tenant()` inconsistent null byte handling vs `with_token()`** at `client.rs:34-51`

`with_token()` rejects the entire token if it contains `\0`. `with_tenant()` strips `\0` characters but keeps the remaining string. This inconsistency means `"tenant\0id"` silently becomes `"tenantid"`, which could cause subtle identity mismatches. Both should follow the same policy: reject entirely or document the stripping behavior.

---

### **[MEDIUM] `AXIATHON_TIMEOUT` parse failures silently ignored** at `config.rs:62-65`, `config.rs:82`, `config.rs:170-171`

Three separate locations parse `AXIATHON_TIMEOUT` and silently fall back on failure:
- `from_file()` line 63: `.and_then(|t| t.parse().ok())` — silent fallback
- `apply_env_overrides()` line 82: `if let Ok(t) = timeout.parse()` — silent fallback
- Builder line 171: `.parse().unwrap_or(30)` — silent fallback

If an operator sets `AXIATHON_TIMEOUT=5m` (thinking it accepts duration strings), the setting is silently ignored. At minimum this deserves a `tracing::warn!`.

---

### **[MEDIUM] Test env var race conditions across parallel tests** at `tests/config_loading.rs`, `tests/security.rs`

Multiple tests call `std::env::set_var("AXIATHON_API_URL", ...)` and `std::env::set_var("AXIATHON_TIMEOUT", ...)` without synchronization. Since `cargo test` runs tests in parallel threads within a process, these can interfere with each other. Tests like `client_config_env_var_overrides_server_url` (line 80) and `client_config_cli_flag_overrides_env_var` (line 173) both manipulate `AXIATHON_API_URL`.

### **[LOW] `RawConfig` silently ignores unknown fields** at `config.rs:15-25`

Without `#[serde(deny_unknown_fields)]`, typos like `server_urll` or `timout` in `cli.toml` are silently ignored. The user gets default values with no indication their config was ignored. The `_token` and `_api_token` fields are intentionally allowed and ignored (which is good for security), but all other unknown fields also slip through.
