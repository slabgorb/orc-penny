# Story 6.1 CLI Framework — Adversarial Code Review

*"I seem to be having this tremendous difficulty with my lifestyle... but I've had my tea, and I've looked at every module, every test, every struct. Let me tell you what I found."*

## Findings

### `[CRITICAL]` Missing `main.rs` — binary cannot be built
**`crates/axiathon-client/src/main.rs` does not exist.** AC-3 requires `main.rs` to catch errors, print to stderr, and call `std::process::exit()` with the correct exit code. The `Cargo.toml` has no `[[bin]]` section either. The `axiathon` binary literally cannot be compiled. This is the single most important deliverable of Story 6.1.

### `[HIGH]` Test suite fails under default `cargo test` parallelism
**`config_loading_test.rs:97-102`** — `client_config_env_var_overrides_timeout` fails when run with default parallel test threads because multiple tests (`env_var_overrides_timeout`, `invalid_timeout_env_var_is_rejected`, `precedence_order`) mutate the same `AXIATHON_TIMEOUT` env var concurrently. Confirmed: passes with `--test-threads=1`, fails without. Tests manipulating process-global state must use `serial_test` or be restructured. This isn't a flaky test — it's a **deterministic failure under `cargo test`**.

### `[HIGH]` `with_env_overrides()` skips URL validation — SSRF vector
**`config.rs:68-82`** — `from_toml()` validates URLs with `validate_url()` (rejects non-HTTP schemes), but `with_env_overrides()` blindly accepts any `AXIATHON_API_URL` value including `ftp://`, `file:///etc/passwd`, or `javascript:` schemes. An attacker with env var control can bypass URL validation. The `with_cli_overrides()` method has the same gap at line 85-97.

### `[HIGH]` `RawConfig` silently accepts unknown TOML fields
**`config.rs:10-15`** — `RawConfig` lacks `#[serde(deny_unknown_fields)]`. A config file with `api_rul = "..."` (typo) or `tokenn = "secret"` is silently accepted. Operators won't know their config is being ignored. While the `token` field is intentionally excluded (good), the lack of unknown field rejection means legitimate config mistakes are invisible.

### `[HIGH]` `init.rs` is empty — should be functional per AC scope
**`commands/init.rs`** — Contains only `pub struct InitArgs;` with no handler. The story scope explicitly states: "Shell completion generation (functional, not stub)" and "`axiathon init` first-time setup (functional, not stub)." Completion was implemented; init was not. This is a scope gap — init should at minimum create the config directory and write a default `cli.toml`.

### `[MEDIUM]` `--tenant` flag accepts raw `String` — no validation
**`cli.rs:36`** — `pub tenant: Option<String>` accepts arbitrary strings. `TenantId::new()` in `axiathon-core` validates UUID format, but the CLI never calls it. An operator passing `--tenant "not-a-uuid"` will get a confusing server-side error instead of an immediate CLI-side validation message.

### `[MEDIUM]` `response.text().await.unwrap_or_default()` swallows body read errors
**`client.rs:96`** — If the response body can't be read (e.g., connection drops mid-stream), `.unwrap_or_default()` silently produces an empty string. For a 200 response, this returns `Ok("")` — the caller gets no indication that data was lost. Should propagate the error.

### `[MEDIUM]` `toml` version mismatch vs story spec
**`Cargo.toml:51`** — Workspace declares `toml = "0.8"` but story technical guardrails specify `toml` 0.9. This may indicate stale spec or intentional divergence (0.9 may not exist yet), but should be documented.

### `[MEDIUM]` `SiemClient` only implements `GET` — no `POST`/`PUT`/`DELETE`
**`client.rs`** — Only `get()` is implemented. Future command handlers (rules create, alerts acknowledge, config set) will need `POST`/`PUT`/`DELETE`. While stubs don't need these yet, the AC-7 description says "SiemClient wraps reqwest::Client" implying a general-purpose HTTP wrapper. This is borderline but worth noting for the next story.

### `[MEDIUM]` `completion.rs` silently returns empty string for unknown shells
**`commands/completion.rs:23`** — The match arm `_ => return String::new()` silently returns empty output for unrecognized shell names. While clap's `value_parser` prevents this at the CLI level, calling `generate_completions("invalid")` programmatically gives no error. Should panic or return `Result`.

### `[LOW]` `SiemClient` header injection test is non-deterministic
**`siem_client_test.rs:224-253`** — The CRLF injection test connects to `127.0.0.1:1` and asserts the error is NOT `ServerUnavailable`. But `HeaderValue::from_str` rejects CRLF before the connection attempt, so the error is `GeneralError`. If the error mapping changes, this test could pass for the wrong reason. Better to test `HeaderValue::from_str` directly.

### `[LOW]` No `tracing-subscriber` initialization anywhere
**`lib.rs`, no `main.rs`** — The `-v`/`-vv` flags are parsed but never wired to `tracing-subscriber` configuration. Since `main.rs` doesn't exist, this is subsumed by finding #1.

### `[VERIFIED]` CWE-209 — `ServerError` Display is sanitized
`error.rs:19-20` — `#[error("server returned an error")]` does not echo the stored body. The inner `String` is `#[allow(dead_code)]`. Confirmed the Display output is generic.

### `[VERIFIED]` CWE-113 — Header injection prevented by `HeaderValue::from_str`
`client.rs:67,74` — Both tenant and token headers go through `HeaderValue::from_str()` which rejects non-visible-ASCII including CRLF. Errors are mapped to `CliError::GeneralError`.

### `[VERIFIED]` Token excluded from Debug/Display output
`client.rs:112-126` — `Debug` impl shows `has_token: bool`, not the token value. `Display` shows only `base_url`. No token leakage.

### `[VERIFIED]` Config token field intentionally excluded
`config.rs:14` — `RawConfig` omits `token` field entirely. `ClientConfig` has no token storage. Serialization confirmed clean.

### `[VERIFIED]` `#![forbid(unsafe_code)]` present
`lib.rs:2` — Applied at crate root.

### `[VERIFIED]` `#[non_exhaustive]` on `CliError`
`error.rs:12` — Correctly applied, allowing future variants.

### `[VERIFIED]` Exit code mapping correct
All 8 variants tested. Auth→3, Authz→4, everything else→1. Matches AC-3.
