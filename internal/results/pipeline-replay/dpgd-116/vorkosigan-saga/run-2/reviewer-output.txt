### [MEDIUM] `--server` flag missing `env = "AXIATHON_SERVER"` — `crates/axiathon-client/src/cli.rs:23`

### [MEDIUM] `ConfigFile` silently ignores unknown fields — `crates/axiathon-client/src/config.rs:4-12`

`ConfigFile` deserializes with serde defaults, meaning unknown/typo'd fields like `srver_url` are silently ignored. This is a common source of operator confusion. Consider `#[serde(deny_unknown_fields)]` to fail fast on typos. Without it, a misspelled field silently falls through to defaults.

### [MEDIUM] Config env var timeout override doesn't validate zero — `crates/axiathon-client/src/config.rs:65-70`

The env var timeout path parses the string to u64 but doesn't check for zero. The file-based path checks `t == 0` at line 53, but the env var path at line 69 sets `config.timeout = t` without the same check. A `AXIATHON_TIMEOUT=0` env var would produce a config with zero timeout that only fails if `validate()` is called separately.

### [MEDIUM] `OutputFormatter` trait methods silently swallow serialization errors with `unwrap_or_default()` — `crates/axiathon-client/src/output.rs:64,99,111,120,123,138,142-143`

Multiple `unwrap_or_default()` calls on serde serialization and CSV writing. If serialization fails (e.g., map keys that aren't strings), the operator gets empty output with no indication of failure. These should at minimum log a warning via `tracing::warn!` or return a `Result`.

### [MEDIUM] `SiemClient` has only a `get()` method — `crates/axiathon-client/src/client.rs:42`

The story is a framework story and subsequent stories will need POST, PUT, DELETE for rules/alerts/ingest management. The client wrapper only implements GET.
