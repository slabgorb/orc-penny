# Story 6.1 Review: CLI Framework & Structure

## Observations

### [HIGH] CWE-113 — Silent header injection swallowing via `if let Ok(val)` at `client.rs:42-45`

When `tenant_id` or `token` contains CRLF characters, `HeaderValue::from_str()` returns `Err` and the header is **silently dropped**. The client proceeds without the `X-Tenant-ID` or `Authorization` header, meaning:
- A request intended for tenant A could hit the default/no-tenant path — **tenant isolation bypass**.
- A request intended to be authenticated silently becomes unauthenticated.

This should return an error to the caller, not silently degrade. The test `siem_client_rejects_tenant_id_with_newlines` actually demonstrates this: it creates the client, makes a request, and the assertion is weak — it accepts *any* outcome including silent success without the header.

### [HIGH] Edition mismatch — `axiathon-client` uses edition 2021 vs workspace 2024 at `Cargo.toml:2`

The workspace declares `edition = "2024"` in `[workspace.package]`, but `axiathon-client/Cargo.toml` hardcodes `edition = "2021"` instead of using `edition.workspace = true`. This breaks the workspace consistency rule and means `axiathon-client` doesn't get edition 2024 features/changes. This is likely a bug, not intentional.

### [MEDIUM] `expect()` in production code — `client.rs:57`

`reqwest::Client::builder().build().expect("failed to build HTTP client")` violates the project rule "No `unwrap()` in production code — use `?` or `expect()` with actionable message." While `expect()` with a message is technically allowed per the rule, in this context the builder can fail (e.g., TLS backend initialization failure) and panicking is inappropriate for a CLI tool. Should return `Result<Self, CliError>` from `new()` and `build()`.

### [MEDIUM] `expect()` in production code — `output.rs:104,109-115`

Multiple `expect()` calls in `render_csv` and `render_json`. While CSV write to `Vec<u8>` won't fail in practice, using `expect()` instead of propagating errors is inconsistent with the project's error handling philosophy. The `render_json` one at line 104 is more defensible.

### [MEDIUM] Config silently accepts unknown fields at `config.rs:8-15`

`RawConfig` uses default `serde::Deserialize` which silently ignores unknown TOML keys. If an operator typos `sever.url` instead of `server.url`, the typo is silently ignored and defaults are used. Consider `#[serde(deny_unknown_fields)]` or at minimum a warning. This is a common source of operator frustration.

### [MEDIUM] `--tenant` accepts raw `String` instead of validated `TenantId` at `cli.rs:29`

The architecture specifies `TenantId` newtype for tenant IDs. The `--tenant` flag accepts any arbitrary string. While validation could happen downstream, accepting garbage at the CLI level (empty strings, whitespace) and propagating it to `SiemClient` as an unvalidated `&str` means invalid tenant IDs reach the HTTP layer.

### [MEDIUM] Config env var tests are not thread-safe at `cli_config.rs:62-118`

Tests use `std::env::set_var`/`remove_var` which mutates process-global state. If tests run in parallel (Rust's default), they can interfere. `set_var` is also marked unsafe in edition 2024 (which the workspace declares), reinforcing the edition mismatch issue.

### [MEDIUM] Nightly `rustfmt` check fails — `cli_siem_client.rs:43,334`

Per project gotchas, nightly fmt must pass before approval. Two formatting violations found.

### [LOW] `init` command doesn't create the config file at `main.rs:30-38`

`axiathon init` creates the parent directory but never writes a default `cli.toml`. It only prints the path. The user gets "initialized" but there's no config file. The AC says "first-time setup" — a skeleton config file would be expected. This is arguably a scope question, but the current behavior could confuse operators.

### [LOW] `main.rs:34,36` — `.ok()` swallows errors silently

`create_dir_all(parent).ok()` and `writeln!(...).ok()` silently discard I/O errors. If the config directory can't be created (permissions), the user gets no feedback. Per the bash rules about never swallowing errors silently, this pattern is questionable.

### [LOW] `OutputFormatter` is a concrete struct, not a trait at `output.rs:39`

AC-4 specifies an `OutputFormatter` **trait** with Table/Json/Csv implementations. The implementation uses a concrete struct with an enum-dispatched method. This works functionally but doesn't match the specified architecture. Future command implementations won't be able to provide custom formatters via trait dispatch.

### [VERIFIED] CWE-209 — Error Display messages are properly generic at `error.rs:12-38`

`ServerError` Display says "server error: please try again later" — does not expose the inner string. `NotFound` Display says "resource not found" — does not expose the URL. Security comment is present. Tested.

### [VERIFIED] Exit codes 0/1/3/4 correctly mapped, 2 handled by clap at `error.rs:46-52`

All CliError variants map to correct exit codes. Binary integration tests confirm code 2 for usage errors.

### [VERIFIED] Token never exposed via config at `config.rs:119-121`

`token()` always returns `None`. Token field in TOML is parsed but dead-coded. Tests verify.

### [VERIFIED] Shell completion generation works for all 4 shells

Binary tests confirm non-empty stdout for bash/zsh/fish/powershell.

### [VERIFIED] All command groups present and plural-noun convention followed

`rules`, `alerts` (plural) — tested. Singular forms rejected — tested.

### [VERIFIED] Stub handlers print story references and exit code 1

All stubs tested via binary integration tests with correct exit code and message.

## Verdict: **CHANGES_REQUESTED**

Two High-severity issues must be addressed:

1. **Silent header dropping** in `SiemClient::build()` — invalid tenant/token must return an error, not silently omit security headers. This is a tenant isolation and authentication bypass vector.
2. **Edition mismatch** — `edition = "2021"` must be `edition.workspace = true` to match the workspace's `"2024"`. This also makes the `set_var` calls in tests unsound under the declared workspace edition.

The nightly fmt failure (Medium) should also be fixed per project gotchas before merge.
