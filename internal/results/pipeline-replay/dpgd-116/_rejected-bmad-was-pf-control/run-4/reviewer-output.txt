## Code Review: Story 6.1 — CLI Framework & Structure

### CRITICAL Issues

**[CRITICAL] Vacuous `matches!` assertions — 7 tests assert nothing** (`cli.rs:257-281`, `client.rs:262,273,284`)

The `matches!()` macro returns a `bool`, but it's used as a bare expression without `assert!()`. These tests *always pass* regardless of what variant is returned:

```rust
// cli.rs:258 — discards the bool, test always passes
matches!(cli.command, Commands::Completion { shell: Shell::Bash });

// client.rs:262 — same pattern, never asserts
matches!(err, CliError::NotFound(_));
```

Affected tests: `completion_command_accepts_{bash,zsh,fish,powershell}`, `check_status_maps_{404,429,500}_to_*`. All 7 are vacuous.

---

**[CRITICAL] `main.rs` never loads config, never builds `SiemClient`, never wires global flags**

The story's Task 1.4 requires main to load config, build `SiemClient`, and pass context to command handlers. Current `main.rs` parses CLI args but ignores `--server`, `--tenant`, `--config`, and `--format` entirely. They are dead flags that do nothing.

---

**[CRITICAL] AC-1 violated: `logout` is not a top-level command**

AC-1 lists `login` / `logout` as separate commands. The implementation nests `Logout` under `Login`, requiring `axiathon login logout` instead of `axiathon logout`. The help text `axiathon login login` (line 127 after_help) also reads awkwardly.

### HIGH Issues

**[HIGH] Config structure doesn't match story spec (AC-8)**

Story specifies nested TOML sections `[api]` with `url`/`timeout_seconds` and `[defaults]` with `output_format`/`default_tenant`. Implementation uses a flat structure (`server_url`, `timeout_secs`, `default_format`). Config files written to the documented format will be silently ignored due to `#[serde(default)]`.

---

**[HIGH] Default server URL mismatch: `localhost:3000` vs story's `localhost:8080`**

`config.rs:11` uses `http://localhost:3000`. Story spec and AC-8 consistently say `http://localhost:8080`. The `init.rs` template also uses `3000`.

---

**[HIGH] Default timeout mismatch: 30s vs story's 60s**

`config.rs:14` defaults to 30s. Story AC-8 says `timeout_seconds: 60`.

---

**[HIGH] `#[serde(default)]` without `#[serde(deny_unknown_fields)]` silently swallows typos**

`ClientConfig` at `config.rs:21` will silently ignore misspelled keys like `servr_url` and use defaults. Combined with the flat-vs-nested mismatch above, this is a config reliability hazard.

---

**[HIGH] `AXIATHON_TIMEOUT` parse failure silently ignored** (`config.rs:84-87`)

If `AXIATHON_TIMEOUT=abc`, the invalid value is silently discarded. This should either warn or error, per the "fail fast" principle.

**[HIGH] `toml` version mismatch: workspace has `0.8`, story requires `0.9`**

`Cargo.toml` workspace line 50: `toml = "0.8"`. Story explicitly calls out upgrading to `0.9` for TOML 1.1.0 support.

**[HIGH] `keyring` dependency unused** (`crates/axiathon-client/Cargo.toml:20`)
