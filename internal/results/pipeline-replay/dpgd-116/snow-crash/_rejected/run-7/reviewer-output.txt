# Story 6.1 Review: CLI Framework & Structure

*The Librarian has examined these archives. The Sumerian tablets were written with care, but the scribes forgot to connect them to the reading room.*

## Observations

### CRITICAL

**1. [CRITICAL] `main()` discards parsed CLI — binary is non-functional** — `main.rs:9`
```rust
let _cli = Cli::parse();
```
The underscore prefix means "intentionally unused." There is no `match cli.command { ... }` dispatch. Running `axiathon rules list` parses successfully and exits 0 — silently doing nothing. This violates **AC-1** (commands must work), **AC-3** (exit codes are never applied), and **AC-10** (stubs should print "not yet implemented" and exit 1). The binary is structurally complete but functionally dead.

### HIGH

**2. [HIGH] `SiemClient::new()` panics via `assert!` instead of returning `Result`** — `client.rs:20`
```rust
assert!(!base_url.is_empty(), "base_url must not be empty");
```
If an operator has a corrupted/empty config, this causes an uncontrolled panic. Per the Rust coding rules: *"No `unwrap()` in production code — use `?` or `expect()` with actionable message."* The doc comment acknowledges the panic (`# Panics`) but this should be `-> Result<Self, CliError>`. The test at `siem_client.rs:191-202` uses `catch_unwind` as a workaround — which itself is a code smell.

**3. [HIGH] CSV/JSON formatters use `.expect()` on all operations — crash vectors** — `output.rs:56,67-73`
Five `.expect()` calls in `CsvFormatter::format_csv()` and one in `JsonFormatter::format_json()`. Writing to a `Vec<u8>` won't fail in practice, but the JSON serializer can fail on non-finite floats (`NaN`, `Infinity`). These should return `Result<String, CliError>` to maintain the error-handling contract.

**4. [HIGH] Silent header drop on malformed tokens — no operator feedback** — `client.rs:50-56`
When a token contains invalid header characters (not just `\r\n` but any non-visible ASCII), `HeaderValue::from_str` fails and the auth header is silently omitted. The operator gets a 401 with no indication that their token was rejected client-side. Should log a warning or return an error.

### MEDIUM

**5. [MEDIUM] `RawConfig` silently ignores unknown TOML fields** — `config.rs:10-15`
No `#[serde(deny_unknown_fields)]` on `RawConfig`. If an operator typos `api_url` as `api-url` or `apiUrl`, the field is silently ignored and defaults apply. This is a common ops footgun. Consider `deny_unknown_fields` or at minimum documenting this behavior.

**6. [MEDIUM] Config-to-CLI integration is absent** — `config.rs` / `main.rs`
`ClientConfig` is never loaded in `main()`. The CLI flags `--server`, `--config`, `--tenant` are parsed but never used to override config values. The precedence chain (CLI flags > env vars > config file > defaults) specified in AC-8 is partially implemented (env > file > defaults) but the CLI flag layer is missing.

**7. [MEDIUM] `AXIATHON_TIMEOUT` env var silently ignores parse failures** — `config.rs:90-92`
```rust
if let Ok(t) = timeout_str.parse::<u64>() {
    self.timeout = t;
}
```
If `AXIATHON_TIMEOUT=abc`, it's silently ignored. Operator won't know their env var had no effect. Should warn or error.

**8. [MEDIUM] `InitArgs` is an empty struct — "functional, not stub" requirement unmet** — `commands/init.rs:4`
The story says init should be functional, not a stub. But `InitArgs` is just `pub struct InitArgs;` with no handler. No `handle()` function, no first-time setup logic.

**9. [MEDIUM] `completion.rs:17` uses `.expect()` on UTF-8 conversion** — `commands/completion.rs:17`
```rust
String::from_utf8(buf).expect("completion output should be valid UTF-8")
```
While clap_complete output is almost certainly valid UTF-8, this is production code using `.expect()`.

### LOW

**10. [LOW] `#[tokio::test]` on non-async tests** — `siem_client.rs:45,57,69,79`
`siem_client_injects_authorization_header` and similar tests use `#[tokio::test]` but don't perform any async work — they just call `default_headers()`. Plain `#[test]` would suffice and be faster.

`cargo +nightly fmt --all --check` reports diffs in `config.rs`, `main.rs`, `cli_structure.rs`, and more. Per `gotchas.md`: *"Always include `cargo +nightly fmt --all --check` in the preflight."* This is a blocking requirement from the gotchas sidecar.

## Verdict

### **CHANGES_REQUESTED**

The implementation has solid architectural bones — the type system, error definitions, CLI structure, output formatters, and security posture are well-designed. But the binary is **non-functional**: `main()` discards the parsed CLI without dispatching any commands. This means:

- No stub messages are ever printed (AC-10 violated end-to-end)
- No exit codes are ever set (AC-3 violated end-to-end)  
- No config is ever loaded (AC-8 partially violated)
- No output is ever produced (AC-4 never exercised)

The tests verify components in isolation but never test the integrated binary. This is the architectural equivalent of building every room in a house but forgetting to install the hallways.

### Required Before Resubmission

1. **Implement command dispatch in `main()`** — match on `cli.command`, call stubs/handlers, catch `CliError`, print to stderr, call `std::process::exit(err.exit_code())`
2. **Change `SiemClient::new()` to return `Result`** instead of panicking
3. **Fix formatters to return `Result<String, CliError>`** instead of using `.expect()`
4. **Run `cargo +nightly fmt --all` and fix all diffs**
5. **Add end-to-end test** that runs the binary and verifies exit code 1 for stub commands

### Recommended (non-blocking)

- Add `#[serde(deny_unknown_fields)]` to `RawConfig`
- Warn on malformed `AXIATHON_TIMEOUT` env var instead of silently ignoring
- Log a warning when a token is rejected by `HeaderValue::from_str`
- Remove unnecessary `#[tokio::test]` on sync-only tests
