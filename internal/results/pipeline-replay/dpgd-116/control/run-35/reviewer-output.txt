### Devil's Advocate

What if this code is broken and I'm missing it?

**The `Unauthorized`/`NotFound` CWE-209 gap is real and underestimated.** The SECURITY comment at `error.rs:7-9` says "ServerError Display intentionally omits the response body" — but then `Unauthorized` and `NotFound` don't follow the same pattern. A 403 response from axiathon-server could contain `{"detail": "user admin@internal.corp lacks permission on /api/v1/tenants/secret-tenant-id"}` and this entire string would be printed to the terminal. In a shared terminal session (screen recording, pair programming, shoulder surfing), this leaks tenant IDs and internal user identifiers. The ServerError pattern was deliberately designed to prevent this — why doesn't Unauthorized follow it? This inconsistency suggests the developer applied CWE-209 mitigation to ServerError (which had a test for it) but not to the other variants that also receive server response bodies.

**The `default_config_path()` relative fallback is insidious.** When `dirs::config_dir()` returns `None` (e.g., in a Docker container with no HOME set, a CI environment, or a chroot), the path becomes `.config/axiathon/cli.toml` relative to CWD. If an operator runs `axiathon init` from `/tmp`, the config directory is created at `/tmp/.config/axiathon/`. Later, running from `/home/user`, `axiathon` looks for `/home/user/.config/axiathon/cli.toml` and finds nothing. The operator has a config file they can't find, and the CLI silently uses defaults. This is exactly the class of bug SOUL #4 warns about.

**The `format` flag is a stringly-typed time bomb.** Right now, `--format xml` is silently accepted by clap (it's just a string) and nothing crashes because no dispatch code exists. When `main.rs` is written in a future story, the developer must remember to parse the string to `OutputFormat`. If they forget, invalid format strings pass through silently. The `OutputFormat` enum exists — it should be used at the CLI boundary.

**What about a confused operator?** An operator types `axiathon config set timeout 60` and gets "not yet implemented (Story 6.3)". Fine. But they also typo their config file with `api_ulr = "https://..."` — no error, the default `http://localhost:8080` is silently used. They wonder why their CLI is hitting localhost. The TOML parser accepts unknown fields by default, which is serde's behavior, but it means config file typos are invisible.

**The `run_init` function creates a directory but not a config file.** The docstring says it does both. An operator runs `axiathon init`, sees "initialized", edits... what file? There's no file. The function creates the parent directory and prints a path to a file that doesn't exist. The docstring is not just inaccurate — it will confuse anyone trying to use it.
