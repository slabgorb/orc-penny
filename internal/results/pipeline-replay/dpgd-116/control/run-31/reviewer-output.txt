### Devil's Advocate

Assume this code ships to production as-is. What breaks?

**Scenario 1: CI/CD with no config file.** A pipeline sets `AXIATHON_API_URL=https://prod.internal` and `AXIATHON_TIMEOUT=120`. The operator calls `axiathon status`. `load()` finds no `~/.config/axiathon/cli.toml`, returns `Self::default()` — **both env vars are silently ignored**. The CLI connects to... nothing (no default server_url). The operator gets a confusing connection error. They've set the env var correctly but it doesn't work. This is the highest-impact silent failure in the diff.

**Scenario 2: CSV export piped to Excel.** An operator runs `axiathon alerts list --format csv > alerts.csv`. An alert description contains `=HYPERLINK("http://evil.com","Click Here")`. The naive `join(",")` passes this through without escaping. When opened in Excel, the formula executes (CWE-1236). This is a spec violation — AC-4 explicitly says "proper escaping via csv crate."

**Scenario 3: Operator typos.** `AXIATHON_TIMEOUT=30s` (with unit suffix). The `parse::<u64>()` silently fails. The operator's 30-second timeout never takes effect. Requests hang for the default duration and the operator can't figure out why.

**Scenario 4: Malicious tenant ID via deserialization.** An API response deserializes a JSON body containing `{"tenant_id": ""}`. Because `TenantId` derives `Deserialize` without validation, this creates a `TenantId("")` that `new()` would reject. This is pre-existing but not addressed in this PR despite being flagged. It undermines the type system's guarantees.
