## Observations

### [VERIFIED] Exit code mapping — evidence: `error.rs:45-55` correctly maps AuthenticationExpired→3, Unauthorized→4, all others→1 via exhaustive match.

Challenged against subagents: No subagent flagged exit_code mapping. Confirmed correct.

### [VERIFIED] CRLF header injection prevention — evidence: `client.rs:15` `s.replace(['\r', '\n'], "")` strips both CR and LF. Tests at `siem_client.rs:152-173` verify injection is blocked.

Challenged against subagents: type-design flagged "silent sanitization" (medium confidence). I disagree — silent stripping is the safer pattern for defense-in-depth. Rejecting with error would require changing the builder API to return `Result`, which complicates ergonomics for a marginal benefit. The security concern is addressed.

### [VERIFIED] Error messages don't echo raw response body — evidence: `client.rs:52` takes `_body: &str` and the match at lines 53-61 uses hardcoded strings ("access denied", "resource not found", "server returned an error"), never interpolating `_body`.

### [VERIFIED] Config token exclusion — evidence: `ClientConfig` at `config.rs:11-14` has only `server_url` and `timeout_seconds` fields. No `token` field. Serde ignores unknown TOML keys by default, so a `token = "..."` in the file is silently dropped and never enters the struct.

### [MEDIUM] [SILENT] Silent failure on invalid AXIATHON_TIMEOUT — `config.rs:44-47`

```rust
if let Ok(timeout) = std::env::var("AXIATHON_TIMEOUT") {
    if let Ok(secs) = timeout.parse::<u64>() {
        config.timeout_seconds = Some(secs);
    }
}
```

If a user sets `AXIATHON_TIMEOUT=abc`, the parse fails silently and the file/default value is used. The user's explicit override intent is discarded with no feedback. Should return `CliError::Config` when the env var is set but invalid.

### [MEDIUM] [EDGE] Empty AXIATHON_API_URL accepted — `config.rs:40-42`

`AXIATHON_API_URL=""` would set `server_url = Some("")`, which would cause confusing HTTP errors later. Should validate non-empty.

### [MEDIUM] [TEST] Tautological assertion — `config_loading.rs:44-47`

```rust
assert!(
    config.server_url.is_none() || config.server_url.is_some(),
    "Config should handle missing file gracefully"
);
```

This is `true || false` or `false || true` — always true. The test can never fail. Should assert `config.server_url.is_none()` specifically.

### [MEDIUM] [TEST] Env var override tests never exercise override path — `config_loading.rs:99-152`

Tests branch on `std::env::var("AXIATHON_API_URL")`. In a clean CI environment, the env var isn't set, so the tests always take the else branch and only verify that file values are preserved. The actual env override logic is untested. Original `unsafe { set_var(...) }` approach was correctly rejected (edition 2024), but no subprocess-based alternative was implemented.

### [MEDIUM] [TEST] AC-10 stub message not verified — `stub_handlers.rs`

The file header claims "Covers AC-10: Unimplemented commands print 'not yet implemented (Story X.Y)'" but every test only checks `Cli::try_parse_from(...)`. No test captures output or checks for the "not yet implemented" message. AC-10 requires stubs to print story references, but the implementation has no handler functions — just unit enum variants with no dispatch logic. For a framework story without `main.rs`, this is acceptable as deferred work.

### [LOW] [TYPE] SiemClient uses `String` for tenant_id instead of `TenantId` newtype — `client.rs:9`

The `TenantId` newtype from axiathon-core validates UUID format. SiemClient accepts any string as tenant_id. Since the value comes from `--tenant` CLI flag (raw user input), validation should happen when converting the string to `TenantId`. Acceptable for framework story; should be addressed when handlers wire tenant validation.

## Design Deviations

### Reviewer (audit)
- **Missing `logout` command:** AC-1 specifies "login/logout" but only `Login` variant exists. No test covers `logout`. Spec says both; code does one. Severity: LOW (test gap, `logout` implementation is Story 9.1 scope).
- **SiemClient doesn't wrap `reqwest::Client`:** AC-7 says "SiemClient wraps reqwest::Client" but `reqwest` is not a dependency. The struct holds raw strings. Acceptable for framework: the API surface (builder, status mapping) is correct, and reqwest integration belongs when handlers make HTTP calls. Severity: LOW (deferred to handler stories).
- **No `main.rs` entry point:** The `axiathon` binary isn't produced yet. All functionality is library-only. This is a natural consequence of the framework-first approach.
