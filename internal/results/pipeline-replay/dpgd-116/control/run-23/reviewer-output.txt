`tenant_id` string → `with_tenant()` → stored as `Option<String>` → (future) injected into `X-Tenant-ID` header. **Gap identified:** `validate_tenant_id()` exists and correctly rejects CR/LF/null/empty, but `with_tenant()` does NOT call it. A caller can bypass validation entirely by calling `.with_tenant("evil\r\nHeader: injected")` directly.

### Blocking Assessment

The **HIGH** finding (`with_tenant()` bypasses validation) is a real security concern. While `validate_tenant_id()` exists as a correctly-implemented static method, it is not called by the builder. The AC-7 spec says "Injects `X-Tenant-ID`" — when that injection happens, unvalidated tenant IDs create a CWE-113 header injection vector. The validation method exists but is dead code from the builder's perspective.

**Fix required:** `with_tenant()` must call `validate_tenant_id()` (and return `Result<Self>` instead of `Self`), or at minimum the builder must validate internally. Similarly, `with_token()` needs CRLF rejection.
