### `[HIGH]` F2 — Test environment pollution causes flaky failures

`config_loading.rs:83-85` sets `AXIATHON_API_URL` and `config_loading.rs:100-101` sets `AXIATHON_TIMEOUT` via `std::env::set_var` / `remove_var`. When tests run in parallel (default), these env vars leak into other tests:

- `config_rejects_zero_timeout` (line 149) — FAILS because `AXIATHON_TIMEOUT=120` overrides the `timeout = 0` in the TOML file, making validation pass.
- `config_rejects_invalid_server_url` (line 159) — FAILS because `AXIATHON_API_URL` overrides `"not-a-url"`, making validation pass.

This is a **race condition** producing non-deterministic test results. `std::env::set_var` is process-global and unsound in multi-threaded contexts (it's `unsafe` since Rust 1.66). The test suite is flaky — it passes sometimes and fails sometimes depending on thread scheduling.
