### [HIGH] CWE-209: `ServerError` Display leaks raw internal error details — `error.rs:21`

```rust

```

The `Display` impl on `ServerError` is safe (static string), but the **inner `String` is accessible via `Debug`** and the test at `cli_security.rs:15-28` (`server_error_display_sanitizes_internal_details`) is **vacuous** — it only asserts the output is non-empty, which will always pass. Meanwhile, `map_http_status` at `client.rs:72` stores `format!("server returned {status}")` which is fine, but the `_body` parameter is ignored. If a future caller passes body content into a `ServerError`, Display won't leak it (good), but Debug will. The test should actually assert the internal message does NOT appear in display.

### [HIGH] Missing `main.rs` binary entry point

There is no `main.rs` in `crates/axiathon-client/src/`. The story requires an `axiathon` binary. The `Cargo.toml` has no `[[bin]]` section and no `main.rs`. The crate is a library only. AC-3 requires `main.rs` to catch errors and call `std::process::exit()` — this is entirely absent.
