### `[HIGH]` Vacuous security tests — header injection asserts nothing — at `security.rs:43-60`, `security.rs:64-73`

`siem_client_rejects_tenant_id_with_newlines` and `siem_client_rejects_token_with_newlines` construct a `SiemClient` with CRLF-injected values, then do `match result { _ => {} }` — this asserts **absolutely nothing**. These tests will always pass regardless of whether header injection is prevented. This is a CWE-113 coverage gap masquerading as a passing test. Either:
1. `SiemClient::new()` should validate inputs and return `Result`, with the test asserting `is_err()`, OR
2. The test should actually make a request through wiremock and verify no injected headers arrive.

### `[MEDIUM]` Missing `logout` command — AC-1 gap — at `cli.rs:50-74`

AC-1 explicitly requires `login`/`logout` in the command groups. The `Commands` enum has `Login` but no `Logout` variant. `axiathon --help` will not show a `logout` command.

### `[MEDIUM]` `--tenant` accepts raw `String`, not validated `TenantId` — at `cli.rs:36`

The `--tenant` flag is `Option<String>`. The project's type design rules require newtypes for IDs: `TenantId(String)` exists in `axiathon-core`. This raw string flows unchecked through to `SiemClient` (`client.rs:51`) and into the `X-Tenant-ID` header. At minimum, basic validation (non-empty, no control characters) should happen at the trust boundary.

### `[MEDIUM]` Config silently ignores unknown fields including `token` — at `config.rs:16-25`

`ConfigFile` uses serde's default `#[derive(Deserialize)]` which silently drops unknown fields. If an operator puts `token = "my-secret"` in their config file, it is silently ignored with no warning. The test at `config_loading.rs:171-189` verifies `token()` returns `None`, but this doesn't verify the operator gets feedback. Consider `#[serde(deny_unknown_fields)]` or at least a warning when `token` is present.

### `[MEDIUM]` Workspace `toml` version mismatch with spec — at `Cargo.toml:55`

Workspace declares `toml = "0.8"` but the story spec says `toml` 0.9. Minor, but deviates from the documented architecture.

### `[LOW]` CWE-209 test is tautological — at `security.rs:16-24`

`cli_error_display_does_not_leak_stack_traces` checks that `ServerError`'s Display output doesn't contain `.rs:`. But the Display is hardcoded to `"Server error: the server encountered an internal error"` — it **never** uses the inner string. The test can never fail regardless of what's stored in the `ServerError(String)` field. A meaningful test would verify the inner detail string is not present via Debug output or that it's inaccessible through Display.

### `[LOW]` `Tui` command has no `after_help` examples — at `cli.rs:73`

AC-2 requires all command help to include `after_help` usage examples. The `Tui` unit variant has a doc comment but no examples block, unlike all other commands.

## Data Flow Trace: `--tenant` → HTTP header

2. Flows to `SiemClient::new(url, Some("my-tenant"), token)` at `client.rs:18`
3. Stored as `Option<String>` at `client.rs:40`
4. Injected as header value at `client.rs:52`: `req.header("X-Tenant-ID", tenant.as_str())`

**Risk:** No validation at any step. reqwest will reject CRLF at send time (not at construction), but other malformed values (empty string, control characters) pass through silently.
