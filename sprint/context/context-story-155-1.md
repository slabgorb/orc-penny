Finish flow marks story done while PR stays open — merge_pr no-op (gh #71/#60)

## Problem
`pf sprint story finish <id>` reports success and transitions a story to **`done`**
(archives the session, updates sprint YAML, removes the session file) while the
story's PR is **still OPEN and unmerged**. The printed step list shows
`2. merge_pr` as if it ran, but the merge is a silent no-op — the code never lands
on the base branch. A `done` story whose code never shipped is a data-integrity
failure and violates SOUL principle "Return Results, Don't Throw" / "No Silent
Fallbacks": finish should fail loud, not report Complete.

Reported in two independent sessions:
- **gh #71** — `pr_number` never recorded (PR created out-of-band via `gh pr create`).
  `merge_pr` is invisible to the out-of-band PR → no-ops → story still flips to `done`.
- **gh #60** — `pr_number` recorded, PR `MERGEABLE`/`CLEAN`, no blocking checks, yet
  `merge_pr` printed but did not merge; story flipped to `done` with commits never on `develop`.

## Root Cause (confirmed in code)
`pennyfarthing-dist/src/pf/sprint/story_finish.py` — Step 2 "Merge PR":
- **L251–263:** merges only `elif pr_number:` via `gh pr merge --squash --delete-branch`.
  On non-zero return it appends a `"warning": "Already merged or failed"` step but
  **proceeds anyway**.
- **L264–265:** when `pr_number` is unset → `{"action": "merge_pr", "skipped": True}`,
  a silent no-op.
- **L287–288:** regardless of merge outcome, `transition_story(..., "done")` runs when
  `pr_merge_mode == "auto"`. There is **no guard** that the base branch actually
  contains the story's merge commit before flipping to `done`.

## Technical Approach
TEA/Dev to confirm and implement during RED/GREEN. Direction suggested by the issues:
1. **Detect open PR by head branch** even when `pr_number` is unset (look it up by
   the story branch), so out-of-band PRs are not invisible to `merge_pr`.
2. **Verify before declaring done:** after `merge_pr`, assert the PR is `MERGED`
   (and/or the base branch contains the merge commit). If not, **abort** — do NOT
   archive/remove the session or flip status to `done`; surface the reason
   (open PR, conflict, required check, protected branch, missing auth).
3. **No silent skip:** when merge is intentionally manual (e.g. `pr_merge_mode ==
   "human"`) or nothing was merged but a branch has unmerged commits, say so
   explicitly with a non-zero/loud signal rather than printing as if it ran.

## Acceptance Criteria
_TEA to formalize as failing tests in the RED phase. Target behaviors:_
- Finish does **not** transition a story to `done` (nor archive/remove the session)
  when the PR is still OPEN / unmerged.
- `merge_pr` finds and merges an open PR even when `pr_number` is unset (by head branch),
  or fails loud if it cannot.
- A merge failure / no-op produces a non-zero / explicit error, not a silent "Complete".
