## Problem
(From gh #90.) When a story's `depends_on` points at a story that has been completed and **archived** (removed from the active merged sprint), the merged-sprint validator raises a hard `ValidationError` ("references non-existent story"). Because `pf sprint story update` and `pf sprint story finish` validate the **entire merged sprint** after writing, one stale reference blocks every story's update/finish sprint-wide — a denial-of-progress from a benign, expected lifecycle event (a dependency finishing before its dependent).

Repro:
1. Story `A` has `depends_on: B`.
2. `B` is finished and archived (moved to `sprint/archive/`).
3. Any `pf sprint story update <other>` or `pf sprint story finish <other>` now fails validation and rolls back, even though the command never touches `A`.

Aggravating factors:
- The error names the dependent story while the operator is working an unrelated one; the owning shard file validates clean in isolation (`pf sprint validate sprint/epic-N.yaml` passes) — only cross-file merged validation fails.
- No CLI affordance to repair: `pf sprint story update` has no `--depends-on` / `--clear-depends-on`, so the only remedy is hand-editing sprint YAML, which framework guidance forbids.

## Technical Approach
Primary fix (issue option 1): **treat a `depends_on` that resolves to an archived/completed story as satisfied, not dangling.** The validator should check the archive (e.g. `sprint/archive/`) before declaring a reference non-existent; a satisfied dep is accepted (optionally surfaced as a warning/info, never a hard error). Truly non-existent references (no active story, no archived story) must still ERROR.

Secondary hardening (issue option 2, in scope if cheap): add `--clear-depends-on` (and optionally `--depends-on <id>`) to `pf sprint story update` so deps are repairable without hand-editing YAML.

Relevant code: validator in `pennyfarthing-dist/src/pf/sprint/` (see `_validate_depends_on` — note sidecar pattern: it currently only validates `epics[].stories`, not `standalone_stories`; story 160-2 covers that separately — don't expand scope). Archive lives at `sprint/archive/`.

## Scope
- In scope: merged-sprint `depends_on` validation treating archived/completed stories as satisfied; regression tests; optionally `--clear-depends-on` CLI flag.
- Out of scope: validation scoping redesign (issue option 3), auto-pruning deps at finish (option 4), the secondary PR-detection observation in gh#90 (file separately), story 160-2's standalone_stories gap.

## Acceptance Criteria
1. A `depends_on` referencing a story present in `sprint/archive/` (completed) passes merged-sprint validation — `update`/`finish` of unrelated stories succeed.
2. A `depends_on` referencing a story that exists nowhere (active or archive) still fails with the existing ValidationError.
3. Regression test covering the gh#90 repro (dep archived → sprint-wide update/finish unblocked).
4. Existing validator tests still pass.
