## Problem
From gh #146. Two distinct truthfulness bugs in 'pf jira assign KEY USER'. (1) --dry-run reports FALSE-POSITIVE SUCCESS: it echoes the input verbatim and prints 'Assigned ...' without resolving the user against Jira, so 'pf jira assign MSSCI-18553 slabgorb@gmail.com --dry-run' prints success while the real call then fails 'User not found'. The dry-run is useless for validating an identifier before a live call. Same false-positive-success pattern reportedly exists in 'pf jira sprint add' — audit other --dry-run paths. (2) The 'email or GitHub username' contract is ambiguous: 'email' must be the Jira ACCOUNT email (corporate SSO, e.g. keith.avery@1898andco.io), not any personal email; a non-Jira email looks valid until the real call. Only the GitHub username resolved in the live session. Fix: make --dry-run perform the real user lookup and fail loudly (User not found: X) without mutating the issue; print the RESOLVED Jira account (email + display name) it will assign to in both dry-run and real output; clarify help text ('USER: GitHub username, or the user Jira account email; non-Jira emails will not resolve').
