## Problem

Portrait sourcing is fragmented across multiple fallbacks (local install, symlinks, theme-siblings, npm packages), creating maintenance burden and cache-poisoning vulnerabilities. The R2 CDN is the canonical source, but the resolver still checks stale local paths first. A poisoned cache entry (LFS stub, truncated file) isn't detected and can silently break the TUI for a user.

## Technical Approach

Eliminate all local portrait installation, override, and fallback paths. Make the R2 CDN (via `portrait_cdn.fetch_portrait()`) the single source of truth. Add PNG magic validation on the cache-hit path so a poisoned stub entry self-heals by discarding and re-fetching.

### Changes Required

1. **Kill `init._install_portraits`** (`pennyfarthing-dist/src/pf/init/core.py:1184`)
   - Remove the symlink-to-shared-cache behavior (line 1272)
   - Remove the function definition and all calls at lines 439 and 485

2. **Remove `--force-portraits` CLI flag** (`init/cli.py:17`)
   - Remove the flag definition
   - Remove `force_portraits` parameter threading through `init_project()` (core.py:344)

3. **Kill theme-sibling and npm package fallbacks** (`portrait_resolver.py:190-203`)
   - Remove theme-sibling (~/.pennyfarthing/portraits/<theme>) lookup at line 143
   - Remove Cyclist npm package fallback at lines 190–203

4. **Add PNG magic validation** (`portrait_cdn.py:145-149`)
   - On cache hit: validate PNG magic bytes (0x89 'P' 'N' 'G')
   - If magic check fails: discard stub entry and re-download from CDN
   - Log each self-heal event for observability

### Result

R2 CDN becomes the only portrait source. No managed local copies, no install step, no symlinks, no overrides, no package fallbacks. Users always get current portraits or a clear error if the CDN is unreachable.
