Setup gap: repos.yaml-declared repos never checked on disk; init materializes over broken symlinks; add remote: field + doctor topology check + relink (gh #98)

## Problem
(From pennyfarthing gh #98.) On the orchestrator project, the inlined `pennyfarthing/` repo was missing (not cloned), yet every health signal was green — `/pf-setup` and `pf doctor` both passed while the dogfood symlink topology was completely broken.

Three compounding gaps:
1. **`project-setup` step-02 detects missing subrepos from `.gitignore` patterns only** (greenfield path). When `repos.yaml` exists and declares `repos.X.path`, nothing cross-checks the declared path exists on disk.
2. **`repos.yaml` has no `remote:` field** — even if the gap were detected, setup has no clone URL. The topology knows path, branch strategy, symlink map — but not where the repo lives.
3. **`pf doctor` validates the runtime, not the topology.** `pf init` falls back to materializing dist content as real directories when a symlink target is missing; doctor checks "content dirs present" and passes even though every declared symlink is broken (tracked symlinks replaced by dirs, showing as deletions in git status). The fallback is resilient for runtime but silently severs the dogfood loop.

Repro: repos.yaml declares an inlined repo + symlink map; target repo not cloned → `pf init` materializes silently → `pf doctor` passes → `/pf-setup` discovery never flags it.

## Technical Approach
Per the issue's suggested fixes (all in scope unless cost forces a cut — discuss as deviation):
1. **`remote:` field** in the repos.yaml schema (clone URL per repo).
2. **Doctor topology check:** every `repos.yaml` repo path exists on disk; every declared symlink resolves to its declared target. Broken topology = FAIL, not silence.
3. **Setup discovery:** when `repos.yaml` exists, treat it as source of truth for expected repos; flag missing ones (offer clone using `remote:` where present).
4. **`pf init` loud warning:** when materializing because a symlink target is missing, name the missing repo instead of silently copying.
5. **Relink affordance:** `pf init --relink` or `pf doctor --fix` replacing materialized copies with declared symlinks once the target repo exists.

Relevant code: `pennyfarthing-dist/src/pf/` (doctor, init, setup/project-setup steps); repos.yaml schema/parsing; the orchestrator's own `.pennyfarthing/repos.yaml` is a live example of the topology format.

## Scope
- In scope: repos.yaml `remote:` schema addition, doctor topology validation, setup discovery cross-check, init materialization warning, relink affordance.
- Out of scope: unrelated doctor checks, npm-era config cleanup (separate stories in epic 157), changing the symlink fallback behavior itself (materializing stays — it just gets loud + repairable).

## Acceptance Criteria
1. `pf doctor` FAILS (with actionable message) when a repos.yaml-declared repo path is missing on disk, or a declared symlink doesn't resolve to its declared target.
2. `repos.yaml` accepts an optional `remote:` per repo; schema/validation covers it.
3. `pf init` emits a loud warning naming the missing repo when it materializes instead of symlinking.
4. A relink path exists (`pf init --relink` or `pf doctor --fix`) that replaces materialized copies with declared symlinks when the target exists; idempotent and safe (does not destroy content when target is absent).
5. Existing init/doctor/setup tests still pass.
